# Security Policy

## Supported Versions

We actively maintain and provide security updates for the latest versions of the platform:

| Version | Supported          |
| ------- | ------------------ |
| 1.x     | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

The BidBattle team takes the security of our platform, user data, and infrastructure very seriously. If you believe you have discovered a security vulnerability, we appreciate your help in disclosing it to us responsibly.

### How to Report

**Please DO NOT open a public GitHub Issue for security vulnerabilities.**

Instead, report the vulnerability using one of the following methods:

1. **GitHub Private Security Advisory:** Open a report privately via the [Security Advisory](https://github.com/Jatyon/bid-battle/security/advisories/new) tab on GitHub.
2. **Email Disclosure:** Send an email with full technical details to the project maintainer with the subject `[SECURITY VULNERABILITY] BidBattle`.

### What to Include

To help us triage and resolve the issue quickly, please provide:

- A detailed description of the vulnerability.
- Step-by-step reproduction instructions or a minimal Proof of Concept (PoC).
- Potential impact and affected components (e.g., Auth, WebSocket Gateway, File Upload, Database).
- Any recommended mitigations or patches, if available.

### What to Expect

- **Acknowledgment:** We will acknowledge receipt of your vulnerability report within **48 hours**.
- **Assessment:** We will confirm the issue, assess its severity, and determine an appropriate fix.
- **Resolution:** A patch will be developed, tested, and deployed to production.
- **Disclosure:** We will coordinate with you regarding public disclosure and credit once the patch is live.
